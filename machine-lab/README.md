# Machine Lab — Work, Force & Motion

A static grade-8 physics app deployed at `/machine-lab/`. No accounts, dependencies, tracking or automatic student-data uploads. The two-page `worksheet.pdf` is independent of the larger app curriculum; its worked teacher key is provided separately.

## Use

- **Balance (default):** each problem exposes one adjustable mass or machine dimension. Drag its marked handle or enter a value, then press Run & test (or Run) to simulate the actual setup. Feedback reports whether it balances and which way the output moves, without revealing the answer or substituting a solved value. All other givens stay fixed. Next problem changes the adjustable quantity, measurements and machine geometry; there are no separate level selectors. Gear arms is available in this activity.
- **Practice:** enter one force, balancing mass, work distance or acceleration. Ideal mechanical advantage remains part of the visual explanation, not a second answer field. Mixed practice develops all four skills. An incorrect numerical answer immediately reveals the correct value while simulating the submitted value; the correction remains until the student chooses another problem. Each correct answer advances that skill through the machine's stages; two misses generate another problem at the same or an easier stage. Complete all four skills to advance to the next machine. Automatic advancement can be switched off.
- **Goals:** exact balancing mass; smallest whole-number input force that starts lifting from rest; input distance for a specified rise; or initial acceleration. The exact force threshold only balances—the minimum whole-number force is the next larger integer. Next problem varies dimensions, ramp slope, gear tooth counts and pulley systems, not just load mass.
- **Auto balance:** resizing a mass or changing geometry adjusts its counterpart to balance. Run stays active at equilibrium or a travel stop, ready for another live pull. The friction / drag slider starts at zero (ideal); Light, Medium and Strong provide increasing viscous resistance. Its setting persists across problems, machines and modes for the current visit. Changing it live preserves position, velocity and the energy ledger. The comparison animation changes between separately balanced setups; it does not model a machine changing shape without external work.
- **Clean numbers:** mass resizing snaps to 0.5 kg; dimension dragging follows each Settings increment; horizontal ramp run snaps to 0.1 m. Generated practice uses compatible givens: whole-number lifting force, 0.5 kg balancing mass, 0.1 m/s² acceleration, and 0.01 m distance pairs (0.001 m only when the stroke cannot fit a two-decimal pair). Physical motion stays continuous. In Practice, rounded custom answers are explicitly labeled and accepted; correct balance/distance tests use their exact physical target. Balance activity instead tests the entered setup itself and never replaces it with an answer. Approximation marks distinguish rounded computed masses from exact model values.
- **Manipulation:** drag a mass face to grip/pull it. Drag its sides or corners to change mass, or type an exact value. Drawn square area is proportional to mass. Balance activity exposes only the assigned edit; the other masses and dimensions remain fixed. Mass changes and geometry edits start a fresh energy experiment. Edits that change a challenge's givens must be restored to earn progress.
- **Comparison:** foreground trajectories have adjustable thickness. Compare paths & weights pauses motion and captures a snapshot with three manually selected stages. Exactly two solid distance lines—one input and one output—keep their lengths, positions and physical scale through every stage. Their labels explain the distances being compared; there are no duplicate path lines or dotted guides. Mass-square areas and product rectangles appear without resizing the lines. No timer advances the comparison. Products are only labeled equal when they actually match. At rest, a labeled reference movement avoids claiming that work has been done. Applied-force setups use force products rather than mass alone.
- **Workspace:** a compact menu places modes, machines and tools together. The main question, single editable value, test feedback and navigation fit a Chromebook-sized viewport. Question, settings, hints, plot, comparison and mass/motion panels have draggable handles and a Reset layout control. Compare is off initially.
- **Pulley / syringe variety:** fixed guides and one/two/three moving-pulley setups show 1/2/4/6 numbered supporting strands. Next problem selects the rope arrangement; there is no separate supporting-strands control. The sheaves use actual, larger radii with constant rope length throughout motion. Syringe bores use a fixed screen scale proportional to the square root of piston area, so absolute size changes remain visible even at equal area ratios.
- **Ramp:** a larger ramp view makes the slope and block clearer. One pulley at the top redirects the rope to the hanging input mass. Drag or enter horizontal run while holding height fixed; changing height preserves the current horizontal run. Slope length is recalculated with the Pythagorean theorem, within the 5 m limit. In Balance activity, only the assigned ramp dimension is editable.
- **Gears:** the gears sit horizontally beside each other. Both rope drums are fixed at radius 0.1 m, so force advantage depends on output teeth / input teeth. Different problems vary tooth counts rather than drum size.
- **Gear arms:** two externally meshed gears sit horizontally beside each other, each carrying a rigid arm that initially extends left. Equal fixed arm lengths isolate the gear ratio. Endpoint masses are secured to the bars and do not swing independently. Run tests balance with both arms horizontal; moving unequal gears away from horizontal changes the torque balance.
- **View:** wheel/pinch or buttons zoom; dragging the background pans. Independently toggle trajectories, force vectors, mass/acceleration, comparisons and plots. Compare actual path length, work displacement, or forces. Plot work displacement, cumulative path length, acceleration, or force against its corresponding work displacement.

Progress, current setup and preferences autosave in this browser on this device; **Save** also saves immediately. **Share** opens a progress summary and recent tests, with an optional student name. **Copy progress link** creates a snapshot link for the student to send; Download backup and Open saved file provide an optional file-based route. A shared link or imported file opens as a preview without replacing existing saved work. Only **Continue from this progress** adopts it; **Keep my progress** leaves the current work intact. Resuming restores the setup paused and at rest, without restoring motion. Balance reports do not include solutions. Nothing is automatically sent to a teacher, and copying a snapshot link does not keep it updated with later work.

Both the stage and interface support light and dark themes. Free play and loose weight tokens have been removed.

## Newtonian simulation

`physics.js` numerically integrates a single generalized coordinate constrained by each machine. Newton's second law, or its rotational equivalent, determines acceleration from the actual connected mass inertia and applied forces. Undamped motion uses velocity-Verlet substeps at most 1/240 s (1/1200 s for levers). With viscous settling, linear machines use the exact piecewise exponential solution and levers use fourth-order Runge–Kutta at 1/1200 s or smaller. Gear arms uses fourth-order Runge–Kutta with or without resistance, resolving both coupled angles and their changing gravitational torques. Frame dt is bounded, and travel-stop collisions account for lost kinetic energy. This is a constrained ideal-machine simulator, not a general collision sandbox.

Gravity is rounded to g = 10 m/s². Machine parts and ropes are massless; ropes are inextensible; friction is absent during free motion when Friction / drag is zero. Increasing the slider applies an output-side viscous force with a requested decay rate from 0 to 3 s⁻¹ in steps of 0.05 s⁻¹, reduced if needed to keep the rope taut. This models speed-dependent drag, not Coulomb surface friction; it is zero at rest and supplies no centering force. Lever and gear-arm endpoint loads are secured and do not swing independently. Hydraulic fluid inertia and hydrostatic pressure-height differences are neglected.

At balance, or steady motion without resistance, F1*d1 = F2*d2. Weight is m*g; the shared g cancels from the balancing equation m1*g*d1 = m2*g*d2. Actual moving-body acceleration a does not generally cancel. During acceleration:

`input work + extra actuator/pointer work − load gravitational energy = change in kinetic energy + heat from settling + energy absorbed at stops`.

The ordinary lever and fixed-ratio machines are neutrally stable when balanced: without resistance, a moving release keeps its generalized speed until a stop; a release from rest stays at that position. Optional resistance brings motion to rest at the displaced position. There is no invisible centering spring. An unbalanced system continues toward a physical travel stop. Stops remain inelastic; independent pendulum swinging and elastic impact rebound are not modeled.

Gear arms is different. With input angle q and tooth ratio k = input teeth / output teeth, the gears turn through q and −kq. Input fall is r₁ sin(q), output rise is r₂ sin(kq), and the inertia is m₁r₁² + m₂(r₂k)². The initial horizontal balance requires m₁r₁ = m₂r₂k. With unequal gears, the subsequent gravitational torques contain different cosine factors, so the horizontal equilibrium is semistable: a small displacement on one side can be restored while a displacement on the other side can be driven farther away. The engine models this behavior rather than adding a centering spring. A finite movement after an initially balanced release need not have equal input and output work; their difference changes kinetic energy and may be dissipated.

The ratio shown is **ideal mechanical advantage from geometry**, not a claim that instantaneous dynamic force gain equals the equilibrium ratio. For gear arms, the current vertical-force ratio includes both arm angles; the problem uses its horizontal starting value.

### Live grip

Pointer dragging applies a bounded active grip: a force that supports the load plus a spring and relative-velocity damping term. It never teleports or directly imposes a body position. The resulting signed tangential force is mapped through the correct path Jacobian into the Newtonian equation. Lever and gear-arm tangent forces act through arc distance, distinct from the vertical forces and work distances used by the textbook balance problem.

Forces are capped at 1000 N; each mass is capped at 200 kg. The engine further scales pointer forces when needed to prevent negative rope tension or loss of supported contact. Its actual applied forces, not the requested values, enter both dynamics and pointer-work accounting. This keeps the model within its stated taut-rope/contact assumptions; it does not simulate slack ropes.

### Distance and acceleration distinctions

- Lever: path lengths are circular arcs r*dθ; vertical work distances are r*d(sin θ). Initial vertical-acceleration problems start horizontal and at rest.
- Ramp: the input weight and box have equal actual path travel. The output work against gravity uses the smaller vertical rise. Acceleration questions ask along the slope.
- Pulley: 1, 2, 4 or 6 supporting strands, with the corresponding rope-travel ratio. Radius and stroke vary independently; Next problem supplies the rope count.
- Wheel and geared winch: rim paths and hanging-mass paths are separate. The geared winch uses equal fixed drums, so its ideal MA is output teeth / input teeth.
- Gear arms: endpoint paths are circular arcs with lengths r₁|Δq| and r₂k|Δq|. Gravity work uses each endpoint’s exact vertical change. Horizontal balance is a position-specific condition when the gears have unequal tooth counts.
- Screw: the screw rotates without axial translation; its guided load cannot rotate. Input drum circumference and thread lead set the ratio.
- Wedge: horizontal input and guided vertical load, with an ideal supported contact.
- Syringes: incompressible volume conservation determines displacement; piston areas determine force ratio.

Distance tests use a force-limited, critically damped position actuator. The entered input work distance sets its target; a wrong answer therefore causes the wrong output rise. Its actual accepted force enters the same Newtonian model and extra-work accounting as pointer forces. The actuator holds the new position while the simulation remains running.

## Performance and validation

Physics advances while Run is active, including at equilibrium and travel stops. Hidden tabs pause motion and comparisons. SVG rendering is limited to 30 frames/s, graph history is bounded to 360 samples, and canvases cap device-pixel ratio at 2. Static gear geometry is cached with a size limit. Input events are batched through animation frames; only one advance timer and one active physical animation are retained.

`source/test-balance-challenges.mjs` checks clean, feasible single-edit Balance problems and setup variety. `source/test-gear-arms.mjs` checks coupled angular dynamics, horizontal equilibrium, energy and displaced behavior. `source/test-machine-edits.mjs` checks geometry edit constraints, including ramp run/height preservation. `source/test-value-steps.mjs` checks input grids and rounding. `source/test-challenges.mjs` checks generated ratios, balance, motion limits, initial accelerations, determinism, geometry diversity and value variety. `source/test-actuator.mjs` checks correct and wrong distance entries with both damping settings. `source/test-comparison.mjs` checks path measurements, reference movements, product scaling, inequality and rendering. Physics tests cover signed pointer forces, spring-driven motion, reversals, contact/tension limits and energy accounting. Browser QA covers answer feedback, adaptive progression, zoom, resizing, pulling, numerical controls, all machines and display toggles.

Serve this folder over HTTP. `app.js` owns interaction/adaptation, `balance-challenges.js` and `challenges.js` own problem generation, `scene.js` renders SVG, `comparison.js` produces static manually selected snapshot comparisons, and `physics.js` advances the model. `source/build_worksheet.py` regenerates the unchanged student PDF and worked key after installing `source/requirements.txt`.
